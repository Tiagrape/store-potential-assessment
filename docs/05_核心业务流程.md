# 05 核心业务流程

> 配套流程图见 `design/流程图/*.drawio`（可导入 ProcessOn 查看）。

## 1. 潜力打分流程

```
企业-门店宽表 → 入参校验 → 维度评分 → 加权合成 → 风险扣分 → 分位校准 → 分层 → 输出 score JSON
```

1. **入参校验**：检查宽表含 5 维度块、权重之和≈100%、日期/窗口合法
2. **维度评分**：对 5 个一级维度，按 24 个二级指标公式把宽表映射为 0-100 分（引用 K1/K2 Knowhow）
3. **加权合成**：`raw_score = Σ(维度分 × 权重)`，权重 15/15/30/25/15
4. **风险扣分**：命中缺货/库存占压/断档/低转化/数据可信度 → 扣分
5. **分位校准**：raw → 全库分位（不改变排序，只换标尺）
6. **分层**：≥85 高潜 / 70-84 成长 / 50-69 基础 / <50 低效
7. **输出**：`{potential_score, score_level, score_rank_pct, dimension_scores, risk_deduction, top_drivers, confidence, evidence_chain}`

> 关键原则：**最终分可复算、可解释**。每分都能拆到"维度→指标→证据字段"。

## 2. 标签生成流程

```
企业-门店宽表
   ├─→ 普通标签（规则引擎）——按 calc_logic 直接计算，确定性
   └─→ AI 高阶标签（提示词+推理）——综合多标签+指标，输出带置信度
        ↓
标签 JSON（值 + 置信度 + 证据 + 动作建议）→ 标签库管理后台（治理/审批/发布）
```

- **普通标签**（L1-L3）：规则写死，机器直接算
- **AI 高阶标签**（L4）：判断标准写进提示词，AI 综合推理，输出结构化 JSON
- **约束**：AI 必须引用输入证据；数据不足输出"数据不足"并降置信度，不虚构

## 3. 门店画像流程

```
score JSON + tags JSON + 明细摘要 → AI 画像生成（提示词约束）→ 画像 JSON
（一句话 / 事实依据 / 经营判断 / 推荐动作 / 风险）
```

- **输入**：打分结果 + 标签结果 + 订单/库存/竞品/协议摘要
- **Knowhow 支撑**：K3 场景模板（什么店推什么品类）、K4 动作库（怎么铺货）
- **输出结构固定**，区分"事实依据 / 经营判断 / 推荐动作"，防止 AI 自由发挥

## 4. 模拟圈选流程

```
选择圈选标签 → 运行圈选规则(跑600万门店) → 预估命中规模 → 预估可转化GMV
→ 规则可信度 + 样本预览 → 确认 → 正式圈选推送给企业
```

- **目的**：投放前先算账，避免圈错店浪费企业资源
- **演示态**：当前原型用内置示例值；真实圈选需等真实数据接入

## 5. 标签治理流程

```
定义口径 → 规则/AI提示词配置 → 审批流(发起→数据口径评审→业务审批)
→ 发布/灰度 → 质量监控 → 效果回溯 → 必要时回滚
```

## 6. 数据校准流程（上线前提）

```
600万门店真实分布统计 → 历史成交回流验证 → 迭代调整参数 → 版本化发布
```

- 校准对象：K2 基准卡、打分公式参数、分层阈值、风险扣分系数、季节系数
- 方法：切桶分位（业态×城市×商圈）+ 历史回测 + 迭代
- 原则：只改参数，不改维度树/权重框架/合成公式/口径
